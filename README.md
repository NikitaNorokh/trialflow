# TrialFlow

**A Python data pipeline for clinical trial data ingestion, transformation, and quality validation.**

[![TrialFlow CI](https://github.com/NikitaNorokh/trialflow/actions/workflows/ci.yml/badge.svg)](https://github.com/NikitaNorokh/trialflow/actions/workflows/ci.yml)

TrialFlow is an independent data engineering portfolio project that collects clinical study data from the [ClinicalTrials.gov API](https://clinicaltrials.gov/data-api/about-api), transforms it into a structured dataset, and validates its quality using SQL.

The project demonstrates practical data engineering concepts: API integration, data transformation, SQL-based validation, automated testing, and continuous integration.

## Overview

Working with external APIs requires more than retrieving data. Data must be structured consistently, stored in a usable format, and checked for quality before downstream analysis.

TrialFlow implements a small end-to-end pipeline to demonstrate these practices.

**Key features**
- Extracts clinical study records from a public REST API
- Transforms nested JSON responses into a tabular dataset
- Stores processed data in CSV format
- Runs SQL-based data quality checks using DuckDB
- Tests transformation logic with pytest
- Uses GitHub Actions to automate testing and pipeline validation

## Data Source and Schema

The pipeline retrieves clinical study records from the public ClinicalTrials.gov API.

The processed dataset contains the following fields:

| Column | Description |
|---|---|
| `nct_id` | Unique clinical study identifier |
| `title` | Study title |
| `status` | Recruitment or study status |
| `phase` | Clinical trial phase, when available |
| `condition` | Associated medical condition |
| `start_date` | Study start date, when available |

The current pipeline is configured to retrieve a limited sample of diabetes-related studies.

**Output:** `data/processed/clinical_trials.csv`

The dataset is generated by running the pipeline and is not committed to the repository.

## Data Quality Checks

TrialFlow uses SQL queries executed through DuckDB to identify potential data quality issues.

| Check | Validation |
|---|---|
| `missing_nct_id` | Identifies records without a study identifier |
| `duplicate_nct_id` | Identifies duplicate study identifiers |
| `missing_title` | Identifies records without a study title |
| `missing_status` | Identifies records without a study status |
| `invalid_nct_id_format` | Checks identifiers against the expected `NCT` format |

Each check returns the number of failing rows and a `PASS` or `FAIL` result.

The quality-check script reports whether the dataset passes the configured validation rules.

## Getting Started

### Requirements

- Python 3.12 or a compatible Python version
- pip
- Internet access to retrieve data from ClinicalTrials.gov

### 1. Clone the repository

```bash
git clone https://github.com/NikitaNorokh/trialflow.git
cd trialflow
```

### 2. Install dependencies

```bash
python3 -m pip install -r requirements.txt
```

### 3. Run the data pipeline

```bash
PYTHONPATH=src python3 src/trialflow/pipeline.py
```

This retrieves the study records, transforms the response, and writes the processed CSV dataset.

### 4. Run data quality checks

```bash
PYTHONPATH=src python3 src/trialflow/quality_checks.py
```

This executes the SQL validation checks against the generated dataset and prints the results.

### 5. Run unit tests

```bash
PYTHONPATH=src python3 -m pytest -v
```

The tests validate the data transformation logic, including expected output fields and handling of empty input.

## Continuous Integration

The repository includes a GitHub Actions workflow defined in `.github/workflows/ci.yml`.

The workflow is configured to run on pushes and pull requests targeting the `main` or `master` branch.

It performs the following steps:

1. Checks out the repository
2. Sets up Python
3. Installs project dependencies
4. Runs unit tests
5. Executes the data pipeline
6. Runs SQL data quality checks

The CI status badge at the top of this README reflects the workflow status reported by GitHub Actions.
